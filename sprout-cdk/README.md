# 🌱 Sprout — AWS via CDK (dev + prod)

The entire backend and hosting for Sprout, defined **once** in AWS CDK (TypeScript) and deployable as **two isolated environments**: `SproutDev` and `SproutProd`. Each deploy also auto-generates `config.js` and uploads the site — you never hand-edit config.

**One CDK stack creates, per environment:**
- DynamoDB table `SproutProgress-<env>` (your data)
- Lambda `sprout-progress-<env>` + HTTP API with a Cognito JWT authorizer (the backend)
- Cognito user pool `Sprout-<env>` with managed login + optional Google (auth)
- Private S3 bucket + CloudFront distribution over HTTPS (hosting)

Dev and prod share **nothing** — separate tables, pools, APIs, and URLs. Test on dev, then promote the same code to prod.

## Layout
```
infra/   <- the CDK app (TypeScript)
lambda/  <- Lambda function code (index.mjs)
web/     <- the site (index.html). config.js is generated at deploy — do not add one.
```

## One-time prerequisites
1. **Node.js** (you have it) and **AWS CLI** installed.
2. **AWS credentials for the CLI.** In the AWS console: IAM → your admin user → **Security credentials → Create access key** (CLI use). Then:
   ```powershell
   aws configure
   ```
   Paste the key + secret, and set **Default region** to the one you want everything in — use `us-west-2` (Oregon, closest to BC). Everything (table names, Cognito domain, URLs) follows this region.
3. Install the CDK app's dependencies:
   ```powershell
   cd infra
   npm install
   ```
4. **Bootstrap** CDK once for this account+region (creates a small support stack CDK needs):
   ```powershell
   npx cdk bootstrap
   ```

## Deploy (the fast path)

### 1. Deploy dev — email login works immediately
```powershell
npx cdk deploy SproutDev
```
When it finishes it prints **Outputs**. Open **`SproutDev.SiteURL`** in your browser — the game is live and you can sign up / log in with email right now. Note **`SproutDev.GoogleRedirectURI`** for the next step.

### 2. (Optional) Add Google sign-in
1. **Google Cloud Console** → APIs & Services → **Credentials → Create credentials → OAuth client ID → Web application**.
2. Under **Authorized redirect URIs**, paste the **`GoogleRedirectURI`** output value (it looks like `https://sprout-dev-<acct>.auth.us-west-2.amazoncognito.com/oauth2/idpresponse`). If you'll run prod too, also add the prod one (deploy prod once to see it, or it's the same with `prod` instead of `dev`). One Google client can hold both.
3. Copy the **Client ID** and **Client secret**, set them as environment variables, and redeploy:
   ```powershell
   $env:GOOGLE_CLIENT_ID="xxxx.apps.googleusercontent.com"
   $env:GOOGLE_CLIENT_SECRET="your-secret"
   npx cdk deploy SproutDev
   ```
   The "Continue with Google" button now works on the dev site.

### 3. Deploy prod when dev looks good
```powershell
npx cdk deploy SproutProd
```
(Add prod's `GoogleRedirectURI` to the same Google client if using Google.)

## Your day-to-day workflow
1. Edit code in `web/index.html` (frontend) or `lambda/index.mjs` (backend).
2. Push to dev and test:
   ```powershell
   npx cdk deploy SproutDev
   ```
   Open the dev SiteURL, click around, confirm it's good.
3. Promote the exact same code to prod:
   ```powershell
   npx cdk deploy SproutProd
   ```

Handy commands:
- `npx cdk diff SproutDev` — preview what a deploy would change.
- `npx cdk destroy SproutDev` — tear down the dev environment (dev keeps no data on destroy; prod is set to RETAIN its table + bucket so you can't nuke real data by accident).

## Notes
- **`config.js` is generated by CDK at deploy** with that environment's real Cognito/API/URL values, then uploaded and the CloudFront cache is invalidated. Don't create or commit a `config.js`.
- **Region:** everything follows your `aws configure` default region. Want a different region? Re-run `aws configure`, then `npx cdk bootstrap` for it.
- **Cost:** two environments still run at roughly pennies/month for personal use (DynamoDB on-demand, Lambda, CloudFront, Cognito all have small/again free allowances) — but much of AWS's free tier is only 12 months, so keep a billing budget alarm on. Nothing here pauses like Supabase.
- **Google secret caveat:** for speed, the Google client secret is passed via env var and ends up in the CloudFormation template (visible in your account). Fine for a personal project; for anything serious, move it to AWS Secrets Manager later.
- **First `git` add:** commit the `infra/`, `lambda/`, `web/`, and `README.md`. The `.gitignore` already excludes `node_modules/` and `cdk.out/`.
